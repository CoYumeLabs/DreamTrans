## “连续更新两次，蓝绿抢流量”的验证

代码检查发现：

- Nginx 的路由只有一个颜色目标，没有把蓝绿放入轮询后端列表。已有 WebSocket 可以继续留在旧颜色，新 HTTP 走切换后的颜色。
- 运维 CLI 使用同一生命周期排他锁。用故障镜像中的实际 CLI 做并发锁实验时，`deploy`、`configure-edge`、`rollback` 均在锁被占用时拒绝执行。
- 旧颜色还拥有未完成工作时，不能直接被下一次发布覆盖。后台任务通过部署状态判断是否可领取新工作；已接收的任务可以继续结束。
- 连续发布确实能使两个颜色都变成同一新版，抹掉普通颜色回滚中的不同旧版本。这是已确认的回退缺陷，不能与流量来回争抢混为一谈。

完整应用实验使用交接指定的两个固定镜像、镜像内实际 Go CLI、固定 Nginx、独立 PostgreSQL 与 10 万条合成用量数据，执行：

1. 旧版活动，持续 HTTP 与音频 WebSocket。
2. 升级新版，新 HTTP 进入新版，旧音频在旧版排空。
3. 结束旧音频并完成排空，在新版启动下一条音频。
4. `configure-edge` 再发布同一个新版，新 HTTP 切换颜色，已有音频留在排空颜色。
5. 完成排空后在最终活动颜色运行第三条音频。

## 故障注入如何区分等待位置

以下都使用隔离数据，不是生产现场复现。

| 人工故障 | 实测现象 | 可判断的边界 |
| --- | --- | --- |
| 锁住一个 Edge 节点行约 6 秒 | 两版真实注册约 6 秒；空凭证注册与 settings 约 1–3 ms | 空凭证返回 401 在 SQL 前，不能用它排除数据库等待或证明 HTTP/2 根因 |
| 25 个阻塞注册占满应用数据库池 | profile/access 约 5.5–5.7 秒；readyz 约 2 秒返回 503；settings/health 仍快 | 连接池耗尽能影响大量业务，但不单独解释同窗口纯内存 settings 慢 |
| 配置表读被排他表锁阻塞 | 5 个 prompts 请求两版均依次约 3/6/9/12/15 秒，最终均 200 | 证实应用锁放大；普通行 UPDATE 不会造成该实验的表读阻塞，生产触发条件仍未知 |
| 人工阻塞部署 mode 文件写入 | 新业务 HTTP 等待，health 快，已建立 WS 继续转发 | admission 锁可以区分探针和业务，但不能独自解释已有音频持续慢 |

证据：[注册/池等待](2026-09-21-investigation/registration-db-wait-results.json)、[配置放大修复前](2026-09-21-investigation/config-db-wait-before.json)、入口锁 race 实验（原始 `admission-race-results.log` 未随仓库归档，实验源码保存在附件 `admission-harness/`）。配置查询错误原来被忽略，所以这些慢请求全部成功返回；现有只记录 5xx 的日志无法捕获它们。

## 配置读取修复的语义

数据库读取、写入离开配置快照锁；同一进程一次只做一个刷新。其他读取在刷新或持久化写入期间返回最后一次成功快照，不排队重做 3 秒超时。健康数据库下按需至多每秒刷新一次，远端变更由到期后的下一次读取刷新。刷新发起者仍可能等待一次 3 秒，故障期间保留旧值的行为被明确保留。

启动加载仍需成功读取有效配置，缺失、损坏或数据库不可用会返回错误。更新仍在数据库事务中读取最新行并合并，提交成功后才发布进程内快照；版本号防止更早的刷新覆盖新提交。这个配置只涉及提示词、模型和算法阈值，不是鉴权或计费策略缓存。

## 观测缺口及下一步

用户主动重试后的当前状态见上文，现阶段保持版本与配置不变。下一步若扩大本地实验，应覆盖模拟 AI/RAG 的混合业务、不同数据分布和长时排空。仍缺少原故障同时间窗口的直接应用、固定代理、公网与浏览器关联时序；新一轮正常采样不能倒推出旧故障位置，单独一条历史 settings 慢记录也不能证明所有接口同时在同一层等待。

备用[只读采集器](2026-09-21-investigation/latency-readonly.sh)已完成 Bash 语法、ShellCheck 与独立 Docker/PG 安全验证，本次没有在生产执行。它校验实际镜像、卷、代理身份和路由，并同时采样直连应用、固定代理及可选公网。它不包含认证业务、音频或 Go 进程池/栈采样，采集完成也不等于性能正常；原始 `latency-collector-validation.log`（未随仓库归档）。不建议现在为此改动生产。

后续需要应用内诊断时，应使用受限本地控制接口，记录各 DB 池等待、匿名化 goroutine 函数栈和 admission 外侧的慢成功请求；不得把密钥、SQL 正文、账户内容或音频写入日志。机制核对参考 [Go 连接池文档](https://go.dev/doc/database/manage-connections)、[PostgreSQL 16 锁文档](https://www.postgresql.org/docs/16/explicit-locking.html)、[Nginx reload 文档](https://nginx.org/en/docs/control.html)。

附件中的 Python/Go 驱动是隔离开发实验，不是生产命令，不等同已纳入 CI 的正式回归测试；其历史 `/tmp` 依赖应按脚本说明准备后再运行。
