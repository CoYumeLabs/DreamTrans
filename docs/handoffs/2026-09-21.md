## 2. 用户希望最终交付什么

主站统一负责账户、认证、预算预留、计费账本、历史记录、知识库和 Edge 管理；各地区 Edge 仅负责实时音频 WebSocket、供应商连接、字幕与可靠回传。音频不绕主站，每个分片不同步等待主站。

发布目标是主站与 Edge 均具备固定代理入口、兼容迁移、不可变镜像、候选检查、切流观察、后台排空、兼容回切和重启恢复。用户希望最终只运行一条升级命令，不再复制多段下载、校验、工具更新和配置更新脚本。

其他明确要求：

- 保留迁移后的正式数据库、应用卷、密钥、Compose 覆盖配置和新增数据；保留迁移升级兼容处理与测试（早期基线提交 `3763a83`）。
- 生产运维使用 Go CLI + 必要 Bash，不依赖 Python 控制器；系统 Python 不应被卸载。测试驱动中的 Python 不属于生产依赖。
- 安装 CLI 有清晰的进度展示、错误解释和状态输出；后台节点 UI 需要改善，用户不接受大量裸文本输入框。
- Edge 安装尽量由主站下发配置；Cloudflare 账号级 API Key 不应是必填条件；支持节点已有独立 Tunnel。
- Speechmatics 使用主站签发短期凭证，长期 Key 留在主站；不支持对应机制的供应商保留独立手动凭证。
- 持续转录期间发布，需要真实验证有界缓冲、重连、去重、字幕衔接和计费；不能把强杀长连接称为无缝迁移。
- 自动备份必须覆盖数据库、仍存在的应用卷持久数据、配置和蓝绿状态，并验证 R2 回读及隔离恢复。

## 6. 这次故障的证据与已撤回判断

### 6.1 用户实际遇到什么

新 Edge 安装曾出现“无凭证 HTTPS 检查成功，输入一次性注册凭证后超时”。此前空凭证 HTTP/2 POST 超时、HTTP/1.1 POST 返回 401，因此引入了 Edge 控制出站请求统一 HTTP/1.1 的改动。**后续真实注册仍超时，安装故障未闭环。** 无凭证探测成功不等于真实注册成功，也不等于能获取供应商临时凭证。

随后用户反馈全站变慢、转录延迟十几秒。采样时主机负载约 0.09，内存可用约 2.9 GiB，CPU 大部分空闲；没有观察到该采样时刻资源耗尽。主站本机 `/readyz` 约 1.3 ms，用户浏览器 `/healthz` 约 228–260 ms。

浏览器业务请求样本：

| 接口 | 总耗时 ms | 首字节等待 ms |
| --- | ---: | ---: |
| `/api/user/billing/session-costs` | 15075 | 15045 |
| `/api/system/settings` | 6422 | 6392 |
| `/api/user/profile` | 5512 | 5490 |
| `/api/system/access` | 5509 | 5483 |
| `/api/user/billing/statement` | 5202 | 2885 |
| `/api/admin/access` | 3295 | 3285 |
| `/api/user/billing/account` | 2194 | 2138 |

这些来自浏览器历史资源样本，不是同一请求在浏览器、Nginx、应用和数据库的关联追踪。不能把所有首字节等待都计为 SQL 执行时间。

故障时 SQL 等待采集命令因粘贴/heredoc 错误没有成功返回，因此**数据库锁等待和连接池等待并未被排除**。

### 6.2 回退与配置对比

专用工具恢复旧镜像后，用户明确说“全部恢复了性能”。随后比较状态文件两种颜色的 `application_env`，没有差异输出。此证据只覆盖已记录环境值，不覆盖数据库动态配置、浏览器状态或运行时等待。

### 6.3 已经核对的代码和构建差异

- `e163d7b..faf654e` 的主要变化是 Edge 注册返回配置、Speechmatics 临时凭证、Edge/安装器 HTTP/1.1、节点管理页面及 YuAction 纳入仓库。
- 普通主站转录链路、认证中间件、账户/计费处理与查询代码在该区间没有对应改动。主站普通 Speechmatics Token 仍默认 600 秒 TTL；新 Edge 显式使用 60 秒。
- 两个正式镜像的转录前端产物字节一致。各有 32 个前端文件，其中 30 个内容相同；不同的是管理页 HTML 和管理页脚本。
- 两镜像 Go 构建版本均为 1.26.5，模块依赖、构建参数和基础系统包对比未发现差异。
- 新增 provider-credential 流程在请求供应商之前提交数据库事务，不是拿着该节点事务锁等待外部 HTTP。没有证据表明故障时该接口实际被调用。
- `/api/system/settings` 的处理函数是内存读，不查数据库、不调用供应商；所以“给业务表加索引”或“JWT 签发慢”不能单独解释全部慢接口。
- 共享发布中间件、固定代理切流代码在上述版本区间未变。健康接口绕过发布 admission 锁；这是定位时应关注的路径区别，**不是已经发现锁死**。
- 正常切流调用 `nginx -t` / `nginx -s reload`，没有重启主站 systemd cloudflared 的代码。

### 6.4 本地隔离 A/B 测试

两个固定正式镜像、同一个独立 PostgreSQL、57 个迁移、10 万条模拟用量记录，每容器限制 2 CPU，8 个并发请求线程，共 600 次请求。每版本每接口 60 次。

| 接口 | 旧版 P50 / P95 / 最大 ms | 新版 P50 / P95 / 最大 ms |
| --- | --- | --- |
| settings | 1 / 5 / 6 | 1 / 4 / 10 |
| access | 1 / 4 / 5 | 1 / 4 / 4 |
| profile | 4 / 9 / 19 | 4 / 8 / 18 |
| admin/access | 2 / 6 / 16 | 3 / 7 / 8 |
| session-costs | 470 / 682 / 721 | 453 / 657 / 715 |

结论仅是**没有复现**。该测试直接访问应用，不经过生产 Nginx/Tunnel，不覆盖真实供应商音频、完整蓝绿部署模式、长时会话或生产混合业务数据。不能由此排除新版部署引起的问题。

原始结果随本文附在 [comparison.json](2026-09-21/comparison.json)。诊断驱动 [benchmark-fixture.py](2026-09-21/benchmark-fixture.py) 仅供隔离 Docker 环境复现，使用合成账户和测试凭证，会创建/删除自己的容器、网络；不是生产脚本，也没有作为正式 CI 回归测试收敛。再次运行前需核对数据库启动就绪等待等测试工具边界。

### 6.5 不应继续沿用的判断

- 04:19:38 的 1033 和随后 16002 拒绝连接：用户确认是主动 reboot；不能归咎于新版或 Tunnel 自发故障。
- `/healthz` 快：只证明该探针路径当时快，不证明认证 API、转录或账本正常。
- CI 和本地 A/B 正常：不证明已修复生产性能。
- 回退恢复性能：与新版部署明显相关，但还不能区分程序变化、进程状态重置、代理连接状态或其他同期因素。
- 旧的后台 SQL/JIT 优化是更早一次独立排查；不要直接套用来解释本次包含内存接口和音频的全站延迟。

## 8. 建议接手顺序与验收标准

### P0：保留稳定生产，定位性能问题

1. 只读核实活动镜像、代理路由、未排空实例、正式卷与备份最近成功时间。不要打印状态文件中的密钥。
2. 在独立环境启动完整代理/蓝绿模式，重现“升级应用 → 更新 Edge 配置 → 再发布同镜像”的序列；同时有持续转录、账户访问及后台任务。分别测试进程冷启动和长时间运行。
3. 为同一请求关联浏览器耗时、代理连接/上游首字节/总耗时、应用处理耗时及 DB pool 等待。现有代理关闭 access log，应用缺少足够的慢成功请求证据；这是需要补齐的观测缺口。
4. 阻塞采样优先关注所有业务共享的入口锁/中间件、连接等待及数据库池；用 goroutine/block 证据验证，不要仅凭某处存在 mutex 就认定根因。诊断端点须限定本地、避免暴露音频、账户内容及凭证。
5. 用真实音频会话分别量首字字幕和持续字幕延迟，检查用量/结果保存，不以健康接口代替。
6. 修复后必须有能触发问题的回归用例及前后对比。若仍无法复现，明确不确定性，不能用猜测写“根因已修复”。

### P1：修好版本回退与一条命令升级

- 区分“颜色切换历史”“配置发布历史”和“不同应用版本历史”；不能再让两次同镜像部署抹掉最后已知正常版本。
- 同镜像、同环境的升级应幂等；配置更新需要新发布时也应保留可用的不同版本恢复记录。
- 升级工具、主站镜像和新节点安装默认 Edge 版本在同一次协调流程完成，不让用户再跑可能触发第二次主站发布的命令。
- 注入拉取失败、迁移失败、候选失败、观察失败、进程退出和重启；确认状态可恢复，数据库新写入和实际卷不变，旧连接不强杀。
- 单次成功状态需展示实际 digest、当前/上一版本和排空状态。支持逐节点/地区发布，不擅自升级所有已有 Edge。

### P1：Edge 安装与临时凭证闭环

- 区分无凭证探测、真实注册、身份换取、供应商探测和 Tunnel 入站检查；前一阶段成功不能代表后续成功。
