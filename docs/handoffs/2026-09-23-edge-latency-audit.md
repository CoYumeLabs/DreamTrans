# 2026-09-23 伦敦待确定延迟与 JWT 排查

## 范围与结论

用户报告伦敦节点的待确定延迟有时升到约 10 秒，随后恢复，并要求检查实际路由和供应商 JWT 是否暴露给用户。本次检查基于主工作树 `2d2b3fd` 加本次前端修复；没有伦敦 SSH、供应商生产连接或故障时关联追踪，不能宣布伦敦实际延迟根因已确诊。

用户提供的状态为 active blue、websockets=0、pending=0、previous=null。它只说明该采样时刻这个实例没有 WebSocket 和待回传事件。当前 Edge 会话日志在退出时打印，正常录音开始不打印。状态中的 `protocol: 1` 是部署控制协议，不能据此认为音频没有使用 v2。镜像 ID 尚未对应到源码提交。

本次另外只读访问 `https://yufolo.com/api/system/access`，返回 200，当前 `edge_enabled=true`、`edge_control_enabled=true`、`authentication_enabled=true`、`anonymous_api_enabled=false`；本调查机器耗时约 70 ms。这不代表故障时开关或伦敦链路状态，也意味着下面的开关变化复现不能直接套用到生产现场。

## 已复现的行为

| 检查 | 证据 | 实际含义 |
| --- | --- | --- |
| 指定地区与实际路由 | Playwright 使用真实前端，先选择伦敦，再把录音启动时的 `edge_enabled` 响应改成 false；界面仍显示伦敦，但没有 authorize 请求，音频连接为主站 `/ws/speechmatics`。稳定 enabled 对照会请求 `region=eu-west-2` 并连接 `/ws/edge`。 | 是确定的条件性路由缺陷；尚不知伦敦现场是否满足此条件。 |

| 主站续租慢 | 对实际本地 WebSocket 注入一直未返回的 renew HTTP；续租仍阻塞时，音频与部分稿在约 1.05 ms 内通过。 | 音频不逐帧等待主站续租；不排除长时间续租失败最终耗尽额度或租约而断流。测试没有连接真实供应商。 |
| 本地持久化阻塞 | 在 Edge 回传队列锁上注入 300 ms 等待；先到的最终稿等待落盘，后面的部分稿也等待约 305 ms，放开锁后恢复。 | 最终稿落盘和后续供应商读取存在串行依赖；磁盘、队列扫描、进程暂停可能放大延迟。本实验不是伦敦磁盘已经慢的证据。 |

## 本次修复

- 显式选择地区节点时，区域功能不可用会清楚报错，不再静默返回主站。主站响应也不能覆盖显式地区选择，已有 Edge 会话不能转为主站。自动选择和显式主站仍保留正常主站入口。
- 转写诊断增加已建立音频连接的域名、路径和连接次数，来源为实际创建并收到 `RecognitionStarted` 的 socket；断开后清空。不会输出 URL 用户信息、查询串或 fragment。域名可核对浏览器入口，但物理位置仍需核对 Tunnel 和部署。
- 保留模型、max_delay、音频帧长、准确率配置、预付门槛、租约与持久化确认语义。

这次没有改变计费事务或 Edge 持久化模型。消除上表的事务嵌套需要同时处理所有调用方、价格快照一致性和目录更新锁顺序；移除落盘等待也必须保留最终稿和计费证据的持久性，不能把跳过确认当提速。

## JWT 边界

- 浏览器正常接收自己的登录 JWT 和受限 Edge grant；后者绑定节点、会话、代次、Origin、采样率、额度与短期有效期，不是 Speechmatics JWT，也不包含签名私钥、节点身份或供应商长期 Key。
- `/api/edge-control/provider-credential` 需要节点身份。隔离数据库测试使用真实签发的管理员登录 token 和 Edge grant，六种非节点凭证形式均为 401，没有调用供应商签发；节点身份对照成功。
- 既有测试覆盖供应商临时凭证仅用于上游握手、过期拒绝、错误脱敏、审计和浏览器 grant 不含供应商 JWT、撤销后拒发和签发限流。正常音频循环没有重复申请供应商 JWT。
- 不能把结论扩大为所有部署配置下“绝不会向浏览器返回供应商 JWT”：旧 `/api/token/rt` 在区域模式下被禁用，启用计费时默认也被禁用；无计费的旧直连部署或显式开启 `ALLOW_UNMETERED_CLASSIC_TOKEN_WITH_BILLING` 的部署保留直接返回供应商 token 的功能。生产实际配置尚未核实。
- Edge 握手错误和退出日志采用固定分类；上游应用消息仍整体转发，主站部分客户端仍记录供应商原始错误。本次没有观察到真实供应商在错误消息里回显 JWT，也没有证明所有异常消息绝无敏感内容。因此这是正常授权通路的边界验证，不是所有上游异常文本的全面保密证明。

## 其余链路检查

| 环节 | 检查结果与边界 |
| --- | --- |
| 前端部分稿处理 | 50 ms 合并与过期定时器立即更新逻辑已存在；本地持久化、AI 翻译不是等待部分稿的同步网络前置条件。完整前端验证覆盖相关行为。 |
| 采样与编码 | 启动前探测 AudioContext 采样率，识别配置使用该值；worklet 按实际采样率组帧并下混为 mono。仍没有故障设备上探测值与采集值的现场对照。 |
| 浏览器积压 | 发送积压只覆盖客户端音频队列、待组帧字节及 WebSocket bufferedAmount，不能排除服务器、供应商积压或浏览器尚未处理的 worklet 消息。 |
| 主站预付 | 展示余额查询已有独立 worker；必要预付仍同步完成才能发音频。数据库等待及已配置的自动充值可能增加这一步耗时，不能通过绕过扣费消除等待。 |
| Edge 上游限流 | 最多领先供应商确认 10 秒音频/500 帧；不是每次固定睡眠 10 秒。等待最多 10 秒后退出，与“同一连接必然周期性卡 10 秒”不是一回事。 |
| 网络写入 | 音频上行持有流互斥锁写供应商，下行确认和字幕共享浏览器 writer；慢写可以阻塞相关路径。现有代码有写超时，但这不证明现场写入未变慢。 |
| Nginx | 生成配置使用 HTTP/1.1、WebSocket Upgrade、关闭 proxy buffering、长读写超时；尚未检查伦敦运行中的实际配置。 |
| Cloudflare、供应商 | 没有对应时段的 RTT、丢包、Tunnel 重连和供应商部分稿到达时间；本机健康接口不能替代这段链路。 |
| 主机资源 | 默认 Edge 容器内存限制 256 MiB、禁止额外 swap；当前没有伦敦 CPU 积分、cgroup 内存事件、I/O 等待或重启统计。用户空闲状态不足以排除录音时资源抖动。 |

## 现场还需要的最小证据

2. 同时记录“待确定”的实时落后、最近/平均、发送积压、是否仍在持续说话，以及有没有重连。
3. 在伦敦录音仍进行时运行旁边的只读采样脚本：`bash 2026-09-23-edge-latency-collect.sh dreamtrans-edge-9b362559-blue`。它读取部署计数、镜像来源标签、重启/OOM、CPU/内存/I/O 样本、本机健康耗时和已有结构化退出日志；不读取环境、配置密钥、音频或字幕，也不重启服务。

采样若同时确认浏览器连接 `/ws/edge`、目标域名正确、该实例 sockets 仍为 0，应继续核对 Tunnel 入口、实际宿主机/容器及版本。若连接主站，则先按主站路径定位，不能继续以伦敦资源解释它。
