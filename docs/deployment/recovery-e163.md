# 从重复配置发布恢复 e163d7b

此脚本仅用于一次已知的生产恢复：`faf654e` 发布应用后，`configure-edge`
再次发布同一镜像，覆盖了 inactive 颜色中的旧版应用。因此普通 `rollback`
只能恢复上一份配置，不能恢复上一版程序。

`scripts/recover-e163-release.sh /root/dreamtrans` 固定恢复已发布的
`e163d7b82d44bc2646f2758f82c4229f08c9e8cf` 镜像（digest `d32344e29bff71713ccfa39ea19f646d95944dead09f0b754fb6202516462b90`）。
它不是通用降级工具，不接受任意镜像或绕过检查的参数。

恢复先核对实际生产卷、运行容器、源代码提交、控制器二进制、协议与迁移校验和。
旧版 56 个迁移必须与新版完全相同，数据库必须恰好包含新版 57 个迁移。
唯一额外迁移必须是已审核的 `057_edge_provider_audit.sql`（两个新增索引）。
保留两个索引和全部新写入；不执行 SQL 回滚，不还原数据库、应用卷或 `.env`。

旧版没有短期供应商凭证接口，因此恢复取得 Edge 节点和会话表的 SHARE 锁，
确认没有启用/排空中的节点、两分钟内心跳或任何未关闭会话。这一锁保持到切流观察结束，
防止检查与切换之间新授权或节点启用。其他主站账户、转录和计费表不被此锁阻塞。
恢复保留节点身份与签名密钥，关闭 Edge 用户调度，并将新节点安装版本恢复为匹配的旧 Edge。
暂停 Edge 安装及启用操作，待故障修复后再恢复其发布。

脚本在生命周期锁下保存原状态和容器检查结果到 `.bluegreen/recovery-e163.*`（仅 root 可读）。
随后按真实旧版协议重建候选记录，使用原 Go 控制器的 `resume` 执行候选启动、就绪和
功能检查、Nginx 平滑切换、15 秒观察及排空。新请求切入旧版；原有主站连接仍由新版
处理，后台排空策略保持不变。这里不保证既有供应商连接能立即迁移或延迟立刻消失。

如果候选启动失败，当前应用继续服务。修复原因后重跑此脚本，会重新获取 Edge 锁并
验证恢复状态。不要手改状态、删除迁移记录或直接用旧控制器绕过兼容性检查。
已成功恢复时重复执行仅查询状态。原新版仍记录为 previous，可使用正常 `rollback`
前向恢复新版及其配置；它也不撤销数据库写入。

依赖 Bash、Docker、现有 Go 控制器和常见 Ubuntu 系统工具；缺少 jq 时从系统软件源安装。
生产恢复不运行 Python。`scripts/tests/recover_e163_runtime_test.py` 仅是隔离 Docker 测试，
使用两份固定发行镜像，覆盖活动节点拒绝、候选启动失败、重试、数据/配置保留、
重复恢复和前向回切。
