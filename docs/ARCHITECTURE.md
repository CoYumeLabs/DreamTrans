# 架构记录 · 0.1

## 产品边界

YuAction 是教师 / 演讲者的现场工作空间。Yufolo 是转录与个人学习空间。产品目标是一个主持端采集一路音频，同一场转录向多个参与者分发；已通过 DreamTrans 现有接口接入账号登录、会话创建、麦克风转录和字幕归档。

## 当前实现

- Go 标准库 HTTP server：REST 负责提交与管理，SSE 负责服务端向浏览器分发状态。主持端另用 WebSocket 传输 PCM 音频，观众仍只订阅 SSE。
- React / TypeScript / Vite：同源 API、独立路由 `/rooms/{code}`、`/host`、`/display`。
- PostgreSQL：一个活动为一个聚合，`rooms` 行保存公开状态 JSONB、独立 `host_hash` 与 `revision`。所有修改使用 revision 比较交换，避免并发写入覆盖。
- Yufolo 模式以登录账号所有权授权；独立模式的主持人持有随机 256-bit capability，数据库只保存 SHA-256 摘要，通过 Authorization 传递。房间码不是管理凭证。
- 房间码是 8 位随机十六进制，持码者可以读取公开内容、匿名提问。它是现场邀请机制，不适合需要成员名单验证的私密课程。
- 持久化提交成功后才通知浏览器。每次连接先注册订阅再读取最新快照，避免初次读取期间漏掉事件。
- 浏览器依据 revision 丢弃旧数据；重连接收当前完整公开状态。SSE 15 秒心跳也会核对持久化版本。
- 服务端严格解析 JSON、限制请求体 16 KiB；文本由 React 转义，不直接渲染用户 HTML。

## 明确限制

这是用于验证完整交互链路的单实例预览架构，不是已完成容量验证的生产课堂系统：

- 每房间最多 300 个问题、5,000 条最终字幕、200 个 SSE 连接。限额属于资源保护，不是性能承诺。
- 广播为公开快照，最多携带最近 50 条字幕；界面展示最后 8 条字幕，大屏展示最新一条。旧字幕仍保存在 PostgreSQL，但尚无完整导出 / 分页界面。
- 房间内消息聚合存在单行，修改时重写状态，后续长课堂需要把字幕和问题拆成独立表，改为序列化增量事件。
- 通知总线在进程内。多实例写入不会互相覆盖，但跨实例即时通知尚未实现，不能将 15 秒心跳当成跨实例广播的替代。
- 当前 UI 支持原文及一种可选的共享目标语言，使用 Yufolo 的 Speechmatics 原生翻译与计费；观众各自选择目标语言尚未实现。
- 连接 Yufolo 后，活动的私有 integration 字段保存所有者与会话 ID，主持操作必须匹配已登录账号；未连接时保留部署级创建密钥和每房间主持密钥。多主持人角色管理尚未实现。
- 问题公开给持码参与者，尚无审核队列、匿名参与者限额或删除能力。
- AI 回答、知识库、课后存档和学生私有笔记不在当前实现中。

## 代理与运行

默认不信任用户提供的转发头。Compose 中后端不公开端口，并显式开启 `TRUST_PROXY`；Nginx 必须覆盖 `X-Real-IP`，不能将客户端任意提供的值透传。若前面再增加 CDN / 代理，应先配置可信代理的真实 IP 处理。

读取与修改速率按 IP 分开计数。学校共享公网出口可能触及阈值；正式课堂应引入成员 / 访客凭证限流，不能简单放大匿名限额。

Compose 保留数据卷；`docker compose down` 不会删除数据。安装器更新前会备份，账号状态通过 Yufolo 校验；定期备份、数据保留周期与活动成员撤销仍需完善。

可选的 DreamTrans 关联部署使用 `compose.dreamtrans.yml`：复用父部署的 PostgreSQL 数据库账号和数据库，YuAction 表位于独立的 `yuaction` schema。安装脚本通过两个 env 文件加载配置，父配置只读，子配置保存 YuAction 自己的镜像标签和设置。共享数据库配置不等于共享登录授权，当前代码通过 DreamTrans 现有 HTTP / WebSocket 接口执行登录、会话和字幕操作，不直接读写其业务表或扣费。
