# 多供应商请求与计费审计（2026-09-09）

范围：多供应商模型目录与成本编辑、聊天、摘要、自动标题、实时翻译用量、嵌入，以及未打开转录会话时的聊天请求。对照提交 `1db854d` 的实际调用链检查。

## 已修复的问题

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| 空会话使用占位字符串 | 未打开转录会话就聊天，前端发送 `current_session`，后端 UUID 校验返回 400 | 保留空会话 ID，使用后端已有的无转录会话聊天路径 |
| 预扣费丢失供应商 | 聊天、摘要、标题用裸模型名查默认供应商价格，新增供应商即使已经定价和审批仍返回 `billing service unavailable` | 内部计费使用 `provider::model`，仅上游请求使用裸模型名 |
| 结算与响应丢失供应商 | Chat Completions / Responses 返回裸模型名；聊天和实时翻译等调用方将其写入用量 | 适配器将用量标识绑定到实际调用的供应商；未返回模型名时使用请求模型，未返回用量时保留预扣费模型身份 |
| 同名模型成本串用 | 成本编辑器仅匹配模型、服务和计价单位，可能预填另一家供应商价格 | 同时匹配供应商，并排除停用的成本行 |
| 显式供应商仍依赖默认端点 | 已选新增供应商或自带端点，但先加载未配置的默认端点导致失败 | 默认端点不可用时按显式模型或完整自带凭据解析请求配置 |
| 默认模型被清空 | 未设置 `OPENAI_MODEL`，注册表用空字符串覆盖适配器默认模型，预扣费与实际请求不一致 | 保留适配器的默认模型 |
| 关闭摘要仍要求摘要供应商 | 仅配置新增供应商、关闭段落摘要时，转录入库仍先解析默认摘要端点 | 无需生成摘要时直接处理转录文本 |
| 标题忽略模型审批查询失败 | 找不到获批摘要模型或目录查询失败后，继续调用环境默认模型 | 在供应商调用及扣费前明确拒绝，避免使用未经选择的回退模型 |

额外修正文档中的旧 `/` 分隔符，并将嵌入维度校验说明与实际响应校验行为对齐。计费失败现在记录服务端具体原因，方便从通用 503 定位问题。

## 回归证据

- 用修改前的生产代码运行扩展后的 PostgreSQL 测试，重现 `/api/rag/ask` 返回 503：`provider cost rate not found: openai-compatible/llama-3.3-70b`。
- 修复后同一测试通过聊天、标题及摘要三个 HTTP 入口，核对上游裸模型名、供应商凭据以及数据库中的三笔正确供应商结算；每笔 100 输入 token、20 输出 token 的上游成本为 USD 0.000109。
- 适配器覆盖两种协议、默认与新增供应商、含 `/` 的模型名及缺失响应模型名。
- RAG 覆盖仅新增供应商部署中的聊天、摘要、兼容聊天和段落摘要，分别验证有用量及无用量响应；另覆盖关闭摘要时的转录入库和自带端点。
- 浏览器回归覆盖无转录会话的连续聊天，以及两家供应商同名模型的成本预填、修改和审批。

测试中的外部模型服务使用本地 HTTP 替身；数据库计费使用隔离 PostgreSQL。上述证据不等于线上部署验证，也不证明各供应商所有模型均支持全部可选 API 参数。
