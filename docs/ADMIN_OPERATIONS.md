# 后台运营、统计与代理

入口：工作台的「管理后台」→ `/pro/admin`。拥有动态后台角色的普通账户也可见入口；转录中先停止录音再离开工作台。权限从数据库逐次请求读取，撤销角色无需等待 JWT 过期。

## 一次性兑换码

后台「兑换码」可生成 1–1000 个一次性码，设置面值、兑换截止时间、兑换后的额度有效天数、渠道和标签，可搜索、作废和下载 CSV。每批码在服务端就是一个只能凭码领取的来源（`claim_mode='code'`），会出现在「推广邀请」列表；任何活动或代理来源也能在「兑换码」对话框里追加发码。用户在账户面板兑换，需验证邮箱；兑换即归因到该来源，一个账户只能通过一种来源领一次赠送，已通过活动链接或推荐归因的账户不能再兑码。

生成使用 `client_request_id` 去重；相同请求标识和全部参数（数量、面值、渠道、标签、截止、有效天数）重试返回原批次，改变任一参数返回 409。兑换串行锁住账户和码，同码重试返回原额度，不重复充值；兑码同样受来源的暂停、截止和名额限制。门户展示最近 1000 个码、最近 200 条结算；后台显示最近 500 条结算和风控记录。当前批次在生成后可立即完整下载。这些列表明确有窗口限制，不能当作完整账目，完整数据以 CSV 导出和数据库为准。

## 涉钱确认与审计

以下写操作要求 `X-Admin-Confirm: true`，否则返回 428 / `confirmation_required`，响应里的 `action` 和 `error` 说明这次具体会动什么：调整余额、修改套餐/充值档位/计费目录、客户会员与赠送、生成或作废兑换码、代理配置、结算申请与审核、解除分成风控、创建带权益的推广活动、修改组织套餐与配额，以及模型定价和系统设置中带价格/折扣/赠送字段的保存。分流额度起点、账户路由、角色、公告、推广文案编辑等不涉钱操作直接保存。前端展示服务端给出的说明并在确认后重试；取消没有任何变更。确认不是替代服务端鉴权的凭证。

后台写操作先持久化请求审计；审计不可用时拒绝写入。完成后记录 HTTP 结果；若结果更新失败，保留 started 记录供追查，不伪称业务未发生。密码、token、secret、API key 从审计请求中脱敏。推广邀请与公告同样经过此中间件。审计页可搜索并导出当前页。

## 角色与范围

| 内置角色 | 能力 |
| --- | --- |
| 超级管理员 | 基础账户 `super_admin` 全权；动态角色不能赋予这个身份 |
| 运营 / 营销 | 渠道面板、推广邀请、一次性码、公告；不能修改价格或路由 |
| 财务 | 财务统计、价格只读、审计、导出、结算审核；不能执行付款 |
| 技术 | 模型策略、路由、延迟和修改统计、成本只读；不能读单个用户账单 |
| 代理 | 自己的码、归因统计、风控原因与结算申请 |

「角色权限」支持复制内置角色、新建和编辑自定义角色、分配与撤销。内置定义不可直接修改。只能授予自己拥有的权限。渠道非空的角色在服务端限制推广邀请、兑换码、面板和审计；其他没有实现渠道过滤的全局接口拒绝访问。原有组织管理员仍仅管理本组织普通账户。

## 数据面板与口径

`GET /api/admin/dashboard?from=YYYY-MM-DD&to=YYYY-MM-DD&granularity=day|week|month&channel=...`，日期按 UTC、结束日包含在内，最多三年。数据与 CSV 使用同一响应；CSV 对公式开头字符转义。财务数据仅发给有 `finance.read` 的角色，模型指标仅发给有 `metrics.read` 的角色。

- 归因：已兑换批次渠道优先，其次注册时推广渠道，否则 organic。归因是当前规则，不是历史时点快照。
- 漏斗：所选期间注册的用户，截至结束日的领码、首会话、一小时、首充和二充。阶段不是强制递进：不领码直接付费者仍计入付费阶段。
- 留存：兑换后第 1、2、4 周内有转录用量；仅纳入已完整经过观察周的用户，按兑换批次展示。
- 直方图：每个用户每周小时，含零用量，范围边界周截取所选日期。
- 资金及路由：使用计费时快照；历史缺少路由的记录显示 unknown，不能推定为标准或训练。
- 用量毛利：扣费减 gift 消耗、会话结束退差额、上游成本；它不包含会员收入与支付手续费，也不是现金利润。四条路径使用发生时 Free / Pro 快照，退差额按该笔付费部分比例分摊。
- 收入：实际 Stripe 交易，充值、会员、负数退款分别列出；人工加款不算销售收入。档位按实际付款金额。余额和未用额度是当前值，非历史结束日余额。
- 延迟：最终转录的音频实际转发到上游后等待时间；暂停不计入延迟。单会话保存 p50 / p90，异常长会话保留最近 8192 样本。图表是会话百分位的分布，不等于所有句子混合后的百分位。当前采集实时 Speechmatics，不含批量任务排队延迟。
- 修改：定稿文本变化计数，相同重传、被丢弃的旧 partial、仅翻译更新不计入；历史修改次数从新埋点开始，不回填猜测。
- 翻译成本：按关联会话目标语言与模型统计 token 和上游费用，缺少关联的语言为 unknown。

## Stripe 手续费与上游额度

手续费读取 Stripe 的实际 BalanceTransaction，支付尚未产生结算记录时保留 NULL，面板显示待补笔数；首次支付与 `charge.updated` 事件都会尝试补记。自动充值、普通充值和会员付款均接入。USD 结算直接使用实际手续费；非 USD 按已记账美元本金与结算总额的比例换算，同时保留原始币种与最小单位金额。不是根据标价费率估算。需确保 Stripe webhook 订阅 `charge.updated`；失败不会中断用户充值入账。

「分流与额度」配置真实 Speechmatics 起始余额、UTC 起算时刻和训练/标准账号。默认金额为 2000，但日期为空时不估算。消耗累计该账号从起点后的上游费用；日均取最近七天（不足七天按实际经过时间）。用量为零时剩余天数为空。历史未知路由不能自动纳入；该估算也不读取供应商实时账单，外部用量需人工校准起点。

## 代理

先在「代理与结算」配置账户（邮箱或 ID）、分成百分比、现金结算门槛、每日发码限额、固定面值、有效天数、渠道、状态，再分配代理角色。保存时服务端为代理创建或更新一个 `kind='agent'` 的来源：代理门户里的邀请链接 `/invite?code=AG-…` 和代理生成的一次性码共用这套赠送条件。代理生成码时只能选数量和截止日（最多 90 天）；面值、渠道、有效期来自管理员配置。每日发码限额是链接和码共用的：当天通过代理链接注册的人数加上当天发出的码不能超过限额，超过后链接当天关闭、落地页显示邀请无效并退回直接注册。不会变更被邀请客户的定价、训练规则或条款。

通过链接注册或兑换代理的码的账户都归因给该代理；注册起十二个月内的真实充值产生分成，充值时冻结比例；后续修改比例不追改已有分成。退款扣减原支付对应的分成。多次部分退款按累计总额计算新增差额，重复及乱序事件不重复扣钱包或分成。暂停代理只阻止发码和结算，不抹除已有客户之后产生的合法分成。邮箱身份、与代理相同设备、最低使用时长在归因时记录风险原因（挂在归因记录上，链接和码一视同仁），影响佣金可结性，不封禁客户或收回赠送。达到时长后自动满足条件，管理员可注明依据解除误判。

结算：代理申请全部可结余额 → 财务审核 → 基础超级管理员执行。低于申请时门槛以一年有效的 gift 额度结算，否则现金。现金操作只登记已经完成的外部付款，必须填写凭据编号；应用不会主动发起银行转账。申请快照保留金额、门槛与方式；申请、审核、支付和退款共用代理行锁，支付前重新核验，余额不足需驳回后重新申请。已支付的重试不再发放额度。退款晚于支付可能使可结金额为负，在后续收益中抵扣，不自动从银行追回。

## 部署与验证

新增迁移 045–048，安装迁移清单已更新。必须按顺序应用所有尚未部署的迁移（包括此前的 043 / 044）。无新增环境变量。生产的现有训练折扣需管理员核对为 20%；此实现不会自动覆写运营调整过的配置。

“训练开关重开后清空所有选择”按原决定保留以后实施。旧 `/api/token/rt` 无会话结束钩子，仍不支持结束退差额；默认关闭，不能将其视为与受控代理等价。

按仓库 CI 执行完整前端验证及全部 E2E、后端格式/依赖/lint、隔离数据库迁移与完整 race 测试。发布是否完成以具体提交的远端 CI 为准。
